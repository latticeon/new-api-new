## Goal

在当前 `new-api-new` 新版架构上，通过修改核心代码完成以下十项功能及必要后台界面；旧魔改仓库只作为只读参考。按功能形成恰好十个独立 Git 提交，提交信息使用中文，不推送远程。保留已有错误改写、通用客户端会话登录及新版安全、支付合规、计费保护。

1. **返回模型名归一**：可配置开关，将网关支持协议中表示响应模型身份的字段统一为客户端本次请求模型名，涵盖普通 JSON、SSE、Responses WebSocket、Realtime 及经过标准协议处理的插件响应。不改正文、工具参数、模型列表、上游路由、真实 usage 和计费模型；无法识别的插件私有响应不进行盲目递归替换。
2. **API 维护开关**：可配置维护文案，阻止新的模型执行和任务提交，覆盖内置及插件入口，返回协议适配的维护错误（HTTP 可用时为 503），不调用上游、不预扣费、不重试渠道。管理后台和已有任务查询／下载保留；在途生成允许完成，现有 WebSocket 上后续新生成请求也受维护限制。
3. **日志输出量为零／为空免扣费**：渠道级开关，默认关闭。以最终即将写入消费日志的输出 token 数为依据，为零或无值时免除本次文本调用全部费用并退回预扣，成功响应和真实 usage 保留，日志明确标注原因；不检查回答文字，不先写日志后扫描退款，不将缺少 token 的图片／视频任务误判为免费。
4. **Linux 热重启与不断流交接**：后台触发与状态展示，新进程就绪后接新连接，旧进程排空 HTTP／SSE 和已接管 WebSocket；启动失败或就绪超时保留旧服务，重复触发受控。新旧进程的后台任务、异步任务结算不能因交接重复执行。非 Linux 明确显示不支持；不承诺强杀、机器故障、外部代理超时或不兼容数据库升级下的不断流。
5. **数据库日志自动清理**：开关、保留天数和明确的清理范围，复用系统任务执行并展示结果，定时分批且避免重复清理；默认仅消费／错误日志。保护资金业务记录和安全审计，手动清理也有范围保护；支持独立日志库及现有 ClickHouse 路径，不涉及磁盘日志文件。
6. **到账达标自动分组**：支持单笔／累计实际到账额度门槛、来源组及目标组。成功入账事件独立防重累计，不依赖可清理日志或余额反推；不追溯启用前历史，关闭期间不累计，重新启用保留已有累计。普通奖励不计入；管理员正向加额是否计入单独控制。付费订阅不是重复钱包入账，不将周期额度反复累计；存在订阅临时组时保留永久达标资格，订阅结束后应用，避免误回退。
7. **全局充值返利与四类来源配套**：一层直接邀请关系，支持总开关、首次／每次规则、比例、每个被邀请人累计上限、来源参与开关和每元奖励网站额度。公式为“来源金额（人民币元）× 生效比例 × 每元奖励额度”。在线充值／订阅使用成功付款金额并保留币种换算依据；余额购订阅不重复算外部付款。兑换码新增“售价（元）”与是否参与返利；历史无售价码默认不返利，不反推售价。管理员加额新增是否参与返利和收款金额，仅正向增量可触发。金额、比例、规则、来源引用和奖励去向留存快照，重复通知不重复发奖，并发不突破上限；发奖失败不撤销原充值，但有持久可重试状态。首次规则以第一笔符合来源条件的成功业务为准，不因开关重置；历史无法证实的事件不虚构、不补发。奖励默认进邀请人可消费余额，可配置待转邀请额度；不扩展注册奖励延迟发放。
8. **用户管理信息补齐**：保留新版已有信息，补邮箱及验证状态、直观调用次数、邀请码、待转邀请额度、只读账号概况及邀请／返利明细入口；受现有管理权限控制，不新增账号到期业务或更改认证流程。
9. **后台邀请情况**：管理员可见总览、邀请人排行、被邀请人列表和奖励明细，支持分页、搜索、排序及日期／来源／状态筛选。记录展示双方身份、来源编号、计算金额和比例、奖励及未发放原因。订单支付金额与兑换码登记售价／管理员登记收款分开展示，不统称已核验实付。统计基于业务账本，历史缺失明细不伪造，删除展示日志不影响统计。
10. **用户级返利覆盖**：设置归属于邀请人。管理员可设置“跟随全局／开启／关闭”三态；单独开启可覆盖全局关闭，单独关闭可覆盖全局开启。比例未设置继承全局，显式 0% 为零奖励；只覆盖启用状态和比例，仍遵守来源开关、首次／每次规则及累计上限。即使全局停用，保留首次／每次等规则供单独开启用户使用。后台可编辑，用户只能查看自己的生效规则；账本记录实际生效配置。

## Acceptance criteria

- 十项均有对应可操作设置／入口、服务端行为和聚焦回归测试；默认关闭的新增功能不会改变未启用站点行为。
- 模型归一测试验证普通、流式与 WebSocket 的目标字段变化，且计费身份和业务内容不变；维护测试覆盖内置及插件提交、存量查询和长连接后续生成限制。
- 免扣费测试分别覆盖最终输出为零、缺失、正数、预扣退回及普通／流式结算；输出正数但正文为 `0` 仍正常计费，图片／视频计费不受误伤。
- 在真实 Linux 环境验证热重启期间长 HTTP／SSE 请求完成、WebSocket 仍由旧进程服务、新连接可用，以及新进程启动失败回退；验证任务交接不重复执行或发奖。Windows 构建通过且入口明确不支持热重启。
- 分组／返利测试覆盖四类来源的适用规则、重复事件、并发累计／上限、配置快照、历史缺失、不参与事件、零比例，以及用户开关和比例继承覆盖矩阵；同笔余额充值与余额购订阅不会双重返利。
- 数据库变更使用真实 SQLite、MySQL、PostgreSQL 分别验证；迁移覆盖全新数据库与基于基线版本的代表性旧数据库，连续启动／迁移至少两次，数据、索引与唯一性保持。日志清理验证独立日志库及真实 ClickHouse 的受影响路径。最终记录实际版本、命令及结果。
- 前端受影响测试、类型检查 `bun run typecheck`、涉及文件 lint／格式检查和生产构建 `bun run build` 通过；新增文案覆盖全部七种语言，i18n 同步不带入无关修改。
- 后端受影响测试和根模块构建通过；若修改 `relaykit` 或 `tokenkit`，分别在模块内以 `GOWORK=off go build ./...` 验证独立构建；`git diff --check` 通过。
- 十个提交各自聚焦一个功能，可构建且包含相应测试；最终提供十个提交哈希、实际验证结果及尚未通过事项。任何必需环境验证缺失时，不将对应功能声称为已完整验收。

## Boundaries

- 只修改当前工作区的相关项目文件；旧 `new-api` 仓库只读。保留用户未跟踪的 `build.bat` 及其他无关修改，不纳入提交，不改 Git 身份配置，不推送、不部署生产。
- 不实现签到限制／整数奖励、订阅兑换码、账号到期、文件日志自动清理、注册奖励延迟发放，也不重复实现已有被动恢复。
- 不修改受保护项目名称／作者归属，不新增未经请求的 docs 或插件目录文档，不绕过服务端权限或既有支付合规门禁，不伪造 usage、实付或历史账目。
- 临时数据库及 Linux 验证环境仅用于隔离测试，不更改现有数据库服务、系统安全设置或生产凭据；如需安装系统组件、重启机器、使用外部付费资源或访问其他未授权目录，先请求许可。
- 不虚构目前不存在的退款回调；受影响的现有退款路径不得重复发奖或将钱包扣为负数，若发现需要额外确定的退款追偿规则，暂停该部分并询问。
- 当前未发现可用 Linux 发行版及 MySQL／PostgreSQL 测试服务。批准后可尝试准备隔离环境；若无法取得 Linux、三数据库或 ClickHouse 实测条件，明确报告阻塞，不用 mock、交叉编译或单一数据库通过替代强制验收。
